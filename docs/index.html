Send files between Mac, PC and Android on the same Wi-Fi

FileDrop finds the computers and phones on your local network, lets you pick one, and sends files straight to it over TCP. Nothing goes through the internet or a server.

macOS 13+ Windows 10/11 · tested UI, transfer not yet verified Android 10+ iOS · planned

Overview

What FileDrop does and how a transfer flows.

macOSMenu bar icon and popover. Swift / SwiftUI.
WindowsSystem tray icon and popup. Win32 C++ with GDI+.
AndroidApp plus Share sheet target. Kotlin / Compose.
Shared coreC++17 engine for discovery and transfer, used by every app.

How a transfer works

  1. Each device announces itself on the network. Other devices appear in a grid: a laptop icon for Macs, a PC icon for Windows, a phone icon for Android.
  2. You pick a device once. FileDrop remembers it as the default target.
  3. You drop files on FileDrop (or share them on Android). The receiver is asked: Accept or Decline.
  4. If accepted, the receiver opens a one-time TCP server with a random 16-character password. The sender connects, proves the password and streams the files.
  5. Both sides show a circular progress ring, then a small notification when it finishes. The TCP connection is closed.

Using FileDrop on macOS

FileDrop lives in the menu bar. It has no Dock icon.

Send files

  1. Click the FileDrop icon (radio waves) in the menu bar. A rounded popover opens.
  2. Under Devices on the network, click the computer or phone you want to send to. It is highlighted and remembered.
  3. Drag files from Finder onto the menu bar icon. The popover opens; drop on Drop files here to send, or drop directly on the icon.
  4. Wait for the other side to accept. The ring shows progress; click Cancel to stop.

Receive files

When someone sends to you, a dialog asks Receive files from <name>? Click Accept or Decline. Files are saved to ~/Downloads.

Options in the popover

  • Receive files via browser: see Receive from a browser.
  • Hide — don't receive files: see Hide mode. The menu bar icon dims while hidden.
  • Start with macOS: adds FileDrop as a Login Item. macOS may ask you to approve it in System Settings › General › Login Items.
  • Quit: stops FileDrop. Other devices stop seeing this Mac.
  • Close the popover by clicking outside it, clicking the icon again, or pressing Esc.
First launch

macOS asks to allow FileDrop to find devices on your local network. Click Allow, otherwise no devices appear. You can change it later in System Settings › Privacy & Security › Local Network.

Using FileDrop on Windows

Same layout as macOS, in the system tray.

  1. Click the blue FileDrop icon in the tray. On Windows 11 new icons start hidden behind the ^ arrow next to the clock; drag it onto the taskbar to keep it visible.
  2. Click a device in the grid to select it.
  3. Drag files from File Explorer into the dashed drop zone. The popup stays open while you drag; it closes when you click elsewhere, press Alt+Tab or Esc.
  4. Incoming requests show a dialog with Accept and Decline. Received files go to Downloads.

Right-click the tray icon for Open FileDrop and Quit. The popup also has Receive files via browser (see Receive from a browser), Hide — don't receive files (the tray icon dims) and Start with Windows.

Network settings

On first run, Windows Firewall asks for network access: tick Private networks and click Allow. Your Wi-Fi must be set to Private (Settings › Network & Internet › Wi-Fi › your network). On a Public network Windows blocks the broadcast that FileDrop uses to find devices.

Using FileDrop on Android

Send from any app with the Share button, or from the FileDrop app.

Share from another app

  1. In Gallery, Files or any app, select one or more items and tap Share.
  2. Choose FileDrop. A card slides up with the devices on your network.
  3. Tap a device. Sending starts right away; the card closes a moment after it finishes.

In the FileDrop app

  • Select a device, then tap Choose files to send.
  • Incoming requests appear as a dialog in the app, or as a notification with Accept / Decline buttons when the app is in the background.
  • Hide — don't receive files: other devices stop seeing this phone.
  • Receive files in background: keeps FileDrop running after you close the app, shown as a persistent notification. Turn it off to stop FileDrop completely when the app is closed.
Permissions

Allow notifications when asked (Android 13+); otherwise you will not see incoming requests while the app is in the background.

Hide mode

Stay on the network without receiving anything.

  • When you turn it on, FileDrop tells other devices it is leaving, so you disappear from their grids immediately.
  • You still see other devices and can send files to them.
  • If a device still tries to send to you, the request is declined automatically. You are not interrupted; the sender sees <name> is hidden and not receiving files.
  • The setting is remembered. The header shows Hidden · not receiving in orange while it is on.

Receive from a browser

Let a device without FileDrop send you files from any web browser.

  1. In the popover (macOS), tray popup (Windows) or main screen (Android), turn on Receive files via browser. FileDrop opens a web server on a random port and shows its address, for example http://192.168.1.5:51234/. Use the buttons next to it to copy or open the address.
  2. On the other device, open that address in a browser. It must be on the same Wi-Fi. Enter a device name and tap Connect.
  3. Your computer asks Allow “<name>” to connect? Click Accept or Decline.
  4. Once accepted, the page shows a drop zone. Drop files or folders, or tap Choose files on a phone. Both sides show a circular progress; received files go to Downloads as usual.
  • The connection stays open after a transfer, so the other device can keep sending. It ends only when you click Disconnect next to that device, untick the option, or quit FileDrop. The visitor can also click Disconnect on the page.
  • Reloading the page keeps the connection; no second approval is needed.
  • The server is off each time FileDrop starts, and gets a new port each time you turn it on.
  • Hide mode does not affect it: you can stay hidden from FileDrop devices and still receive through the browser.
  • On Android, the address has a share button, and FileDrop keeps running after you close the app while the server is on. Connection requests also appear as a notification with Accept / Decline.

Offer the FileDrop app to visitors

The page also shows a Get the FileDrop app card. It detects the visitor's system (macOS, Windows, Android, iOS) and offers the matching installer, with the other platforms listed below. Downloads need no approval. The card is hidden if the host has no installers.

HostAlways offersExtra installers from
macOSThe running FileDrop.app, zipped as FileDrop-macOS.zip (cached, re-zipped when the app changes)FileDrop.app/Contents/Resources/Packages (copied from build/packages by build.sh) and ~/Library/Application Support/FileDrop/Packages
WindowsThe running FileDrop.exe (statically linked, runs on its own)packages\ next to FileDrop.exe
AndroidThe installed APK, as FileDrop-Android.apkAndroid/data/com.filedrop.android/files/packages

Extra installers are matched by file name: .apk → Android, .exe/.msi → Windows, .dmg → macOS, .AppImage/.deb → Linux, and a .zip whose name contains mac, win or linux. The folder is read again on every visit, so new files show up without restarting the server. The app's own installer wins over a folder file for the same platform.

Security

Traffic is plain HTTP on your local network, not encrypted. Only devices you approve can upload, each with its own random session key tied to its IP address. Turn the server off when you no longer need it. On Windows, allow FileDrop on Private networks when the firewall asks.

iOS (planned)

How the iPhone version will behave once it ships.

  • Sending works from the Share sheet at any time, through a Share Extension. Keep the sheet open until the transfer finishes.
  • Receiving only works while the FileDrop app is open. iOS suspends apps in the background, so an iPhone disappears from other devices about 30 seconds after you leave the app.
  • To avoid Apple's multicast entitlement, the iPhone finds devices by sending a short unicast query to every address on the Wi-Fi subnet instead of a broadcast. The protocol stays the same.

Core library and tests

Build and test the shared engine on its own.

cmake -S . -B build/macOS/core -DCMAKE_BUILD_TYPE=Release
cmake --build build/macOS/core -j
./build/macOS/core/shared/filedrop_tests

The tests run two engines on one machine and check discovery, a 3 MB file plus a nested folder, name conflicts, sending from a file descriptor, and hide mode.

fdcli test tool

A command-line peer, handy as a second device on the same computer. Give it its own --id.

# list devices for 3 seconds
./build/macOS/core/shared/fdcli --id cli --name CLI list
# receive and accept everything into a folder
./build/macOS/core/shared/fdcli --id cli --name CLI --dir /tmp/in listen --yes
# send to a device by name or IP
./build/macOS/core/shared/fdcli --id cli --name CLI send "My MacBook" photo.jpg
# browser receive server, approve every visitor
./build/macOS/core/shared/fdcli --id cli --name CLI --dir /tmp/in web --yes --packages build/packages
macOS Local Network

Tools started from a terminal may be blocked from the LAN by macOS's Local Network privacy setting. If fdcli sees nothing, allow your terminal app in System Settings › Privacy & Security › Local Network.

Build for macOS

The script builds the core with CMake, compiles the Swift sources with swiftc, assembles and ad-hoc signs the app bundle.

./macOS/build.sh
# debug build
CONFIG=Debug ./macOS/build.sh
open build/macOS/FileDrop.app

Output: build/macOS/FileDrop.app, built for the current CPU architecture, minimum macOS 13.

Distribution

The bundle is only ad-hoc signed. To give it to other people, sign it with a Developer ID certificate and notarize it, otherwise Gatekeeper blocks it.

Build for Windows

Use Visual Studio on Windows for real builds. MinGW on a Mac is useful to check that the code compiles.

Install CMake

Visual Studio 2022's Desktop development with C++ workload already includes CMake; use it from Developer PowerShell for VS 2022. Or install it separately:

winget install Kitware.CMake
cmake --version   # needs 3.20 or newer

Build with Visual Studio 2022

Open Developer PowerShell for VS 2022 in the repository root (the folder with CMakeLists.txt):

cmake -S . -B build/Windows -G "Visual Studio 17 2022" -A x64
cmake --build build/Windows --config Release

Output: build\Windows\bin\Release\FileDrop.exe. The test tools are in build\Windows\shared\Release\. You can also open the folder in Visual Studio (File › Open › Folder) and run the FileDrop.exe target.

"CMakeCache.txt missing"

The configure step (cmake -S . -B …) did not finish. Run it first and check that it ends with Build files have been written to. Do not copy a build/ folder from another computer; delete it and configure again.

Cross-compile from macOS (MinGW)

cmake -S . -B build/Windows-mingw \
  -DCMAKE_TOOLCHAIN_FILE=Windows/cmake/mingw-w64-x86_64.cmake \
  -DCMAKE_BUILD_TYPE=Release
cmake --build build/Windows-mingw

Output: build/Windows-mingw/bin/FileDrop.exe, statically linked (about 16 MB), runs on Windows 10/11 without extra DLLs.

Protocol

Plain-text UDP control messages, then one TCP connection per transfer.

UDP messages

Each device listens for broadcasts on UDP port 45454 and also opens a private control port, announced in every message. Packets look like this:

FILEDROP/1 ANNOUNCE
id=272a1a33cd1e48c8
ip=192.168.1.203
name=Tuyen’s MacBook Pro
os=macos
port=55754
TypeMeaning
DISCOVERWho is there? Broadcast; carries the sender's identity.
ANNOUNCEReply with name, IP, control port and OS.
BYELeaving the network (quit or hide).
SEND_REQUESTRequest id, file count, file name (single file), total size.
SEND_RESPONSEaccept=1 with TCP IP, port and 16-character password, or accept=0 (with reason=hidden when hidden).
CANCELCancel a pending request.

Integers are big-endian. Each file is sent as path length, UTF-8 relative path, size, then data. The receiver strips .. and invalid characters so nothing is written outside the download folder, checks free space first, and gives up after 5 wrong passwords.

Browser server (HTTP)

The page lives in shared/web/index.html and is embedded into the core library at build time. Every request except the page, /api/info and downloads carries the session key s, which must match the IP that asked to connect.

RequestMeaning
GET /The web page.
GET /api/infoHost name shown on the page, plus apps: the installers on offer (platform, name, size).
GET /download/<platform>Downloads the FileDrop installer for macos, windows, android… No session key needed.
POST /api/helloBody is the visitor's name. Returns session and client; the host is asked to approve.
GET /api/status?known=…Long poll (up to 20 s) until the state differs from known: pending, accepted, declined or closed.
POST /api/batch?count=&total=Starts one transfer (one drop). Checks free space.
PUT /api/upload?b=&path=Raw file body with Content-Length. The batch completes when count files have arrived.
POST /api/batch/endThe visitor cancelled the batch.
POST /api/byeThe visitor disconnected.

Troubleshooting

Most problems come from the network or from permissions.

No devices appear

  • Both devices must be on the same Wi-Fi network and subnet. Guest networks and routers with AP / client isolation block device-to-device traffic.
  • macOS: allow FileDrop under Privacy & Security › Local Network.
  • Windows: set the Wi-Fi to Private and allow FileDrop in Windows Firewall for private networks.
  • The other device may be in hide mode.
  • Click the refresh button to search again.

The Windows app starts but nothing shows

Look behind the ^ arrow in the tray. If an older build is still running, end FileDrop.exe in Task Manager first: only one instance runs at a time.

Transfer fails partway

The connection stalled for more than 30 seconds, usually because a device went to sleep or left the network. Partially received files are deleted. Send again.

Android stops receiving in the background

Turn on Receive files in background and exclude FileDrop from battery optimization in the phone's settings. Some manufacturers stop background services aggressively.

Cách một lần gửi file diễn ra

  1. Mỗi máy tự báo danh tính lên mạng. Các máy khác hiện thành lưới: icon laptop cho Mac, icon PC cho Windows, icon điện thoại cho Android.
  2. Bạn chọn máy đích một lần. FileDrop ghi nhớ máy đó làm mặc định.
  3. Bạn thả file vào FileDrop (hoặc chia sẻ trên Android). Máy nhận được hỏi: Chấp nhận hay Từ chối.

  5. Hai bên đều hiện vòng tiến trình tròn, xong thì có thông báo nhỏ. Kết nối TCP được đóng lại.

Dùng FileDrop trên macOS

FileDrop nằm trên thanh menu, không có icon trên Dock.

Gửi file

  1. Bấm icon FileDrop (hình sóng phát) trên thanh menu. Một popover bo tròn hiện ra.
  2. Trong mục Thiết bị trong mạng, bấm vào máy tính hoặc điện thoại muốn gửi tới. Máy đó được tô sáng và ghi nhớ.
  3. Kéo file từ Finder lên icon thanh menu. Popover tự mở; thả vào vùng Thả file vào đây để gửi, hoặc thả thẳng lên icon.
  4. Chờ bên kia chấp nhận. Vòng tròn hiện tiến trình; bấm Hủy để dừng.

Nhận file

Khi có máy gửi tới, hộp thoại hỏi Nhận file từ <tên máy>? Bấm Chấp nhận hoặc Từ chối. File được lưu vào ~/Downloads.

Tuỳ chọn trong popover

  • Máy chủ nhận file qua trình duyệt: xem Nhận file qua trình duyệt.
  • Tạm ẩn — không nhận file: xem Chế độ tạm ẩn. Icon thanh menu mờ đi khi đang ẩn.
  • Khởi động cùng macOS: thêm FileDrop vào Login Items. macOS có thể yêu cầu bạn duyệt trong Cài đặt hệ thống › Cài đặt chung › Mục đăng nhập.
  • Thoát: tắt FileDrop. Các máy khác không còn thấy Mac này.
  • Đóng popover bằng cách bấm ra ngoài, bấm lại icon, hoặc nhấn Esc.
Lần chạy đầu

macOS hỏi có cho FileDrop tìm thiết bị trong mạng cục bộ không. Bấm Cho phép, nếu không sẽ không thấy máy nào. Có thể đổi lại trong Cài đặt hệ thống › Quyền riêng tư & Bảo mật › Mạng cục bộ.

Dùng FileDrop trên Windows

Bố cục giống macOS, nằm ở khay hệ thống.

  1. Bấm icon FileDrop màu xanh ở khay hệ thống. Trên Windows 11, icon mới thường bị ẩn sau mũi tên ^ cạnh đồng hồ; kéo nó ra thanh taskbar để luôn hiện.
  2. Bấm vào một máy trong lưới để chọn.
  3. Kéo file từ File Explorer vào vùng thả có viền nét đứt. Popup vẫn mở trong lúc bạn kéo; popup đóng khi bạn bấm ra chỗ khác, nhấn Alt+Tab hoặc Esc.
  4. Yêu cầu nhận file hiện hộp thoại với nút Chấp nhận và Từ chối. File nhận được vào Downloads.

Bấm chuột phải vào icon khay để có Mở FileDrop và Thoát. Popup cũng có Máy chủ nhận file qua trình duyệt (xem Nhận file qua trình duyệt), Tạm ẩn — không nhận file (icon khay mờ đi) và Khởi động cùng Windows.

Cài đặt mạng

Lần chạy đầu, Windows Firewall hỏi quyền mạng: tick Private networks rồi bấm Allow. Mạng Wi-Fi phải đặt là Private (Settings › Network & Internet › Wi-Fi › tên mạng). Với mạng Public, Windows chặn gói broadcast mà FileDrop dùng để tìm máy.

Dùng FileDrop trên Android

Gửi từ bất kỳ app nào qua nút Chia sẻ, hoặc từ app FileDrop.

Chia sẻ từ app khác

  1. Trong Thư viện, Tệp hay app bất kỳ, chọn một hoặc nhiều mục rồi chạm Chia sẻ.
  2. Chọn FileDrop. Một thẻ trượt lên với các máy trong mạng.
  3. Chạm vào một máy. Việc gửi bắt đầu ngay; thẻ tự đóng ngay sau khi gửi xong.

Trong app FileDrop

  • Chọn một máy, rồi chạm Chọn file để gửi.
  • Yêu cầu nhận file hiện thành hộp thoại trong app, hoặc thành thông báo có nút Chấp nhận / Từ chối khi app đang chạy nền.
  • Tạm ẩn — không nhận file: máy khác không còn thấy điện thoại này.
  • Nhận file khi chạy nền: giữ FileDrop chạy sau khi đóng app, có thông báo cố định. Tắt đi thì FileDrop dừng hẳn khi bạn đóng app.
Quyền

Hãy cho phép thông báo khi được hỏi (Android 13+); nếu không, bạn sẽ không thấy yêu cầu nhận file khi app đang chạy nền.

Chế độ tạm ẩn

Vẫn ở trong mạng nhưng không nhận gì.

  • Khi bật, FileDrop báo cho các máy khác là mình rời mạng, nên bạn biến khỏi danh sách của họ ngay.
  • Bạn vẫn thấy các máy khác và vẫn gửi file cho họ được.
  • Nếu có máy vẫn cố gửi tới, yêu cầu bị tự động từ chối. Bạn không bị làm phiền; bên gửi thấy <tên máy> đang tạm ẩn, không nhận file.
  • Lựa chọn này được ghi nhớ. Khi đang bật, dưới tên app hiện dòng màu cam Đang tạm ẩn · không nhận file.

Nhận file qua trình duyệt

Cho máy chưa cài FileDrop gửi file cho bạn bằng trình duyệt web bất kỳ.

  1. Trong popover (macOS), popup khay (Windows) hoặc màn hình chính (Android), bật Máy chủ nhận file qua trình duyệt. FileDrop mở một máy chủ web trên cổng ngẫu nhiên và hiện địa chỉ, ví dụ http://192.168.1.5:51234/. Hai nút bên cạnh để chép hoặc mở địa chỉ.
  2. Trên máy kia (cùng mạng Wi-Fi), mở địa chỉ đó bằng trình duyệt, nhập tên máy rồi bấm Kết nối.
  3. Máy bạn hỏi Cho phép “<tên máy>” kết nối? Bấm Chấp nhận hoặc Từ chối.
  4. Khi được chấp nhận, trang hiện vùng thả file. Thả file hoặc thư mục, hoặc chạm Chọn file trên điện thoại. Cả hai bên đều có tiến trình hình tròn; file nhận được lưu vào Downloads như thường.
  • Gửi xong kết nối vẫn giữ, máy kia gửi tiếp được. Kết nối chỉ kết thúc khi bạn bấm Ngắt cạnh máy đó, bỏ tick tuỳ chọn, hoặc thoát FileDrop. Người dùng trên trang web cũng có thể bấm Ngắt kết nối.
  • Tải lại trang không làm mất kết nối, không phải xin phép lại.
  • Máy chủ luôn tắt khi FileDrop khởi động, và mỗi lần bật lại dùng một cổng mới.
  • Chế độ tạm ẩn không ảnh hưởng: bạn có thể ẩn với các máy FileDrop mà vẫn nhận file qua trình duyệt.
  • Trên Android, cạnh địa chỉ có nút chia sẻ; khi máy chủ đang bật, FileDrop vẫn chạy sau khi đóng app. Yêu cầu kết nối cũng hiện thành thông báo có nút Chấp nhận / Từ chối.

Cho máy khách tải app FileDrop

Trang web còn có khung Cài ứng dụng FileDrop. Trang tự nhận ra hệ điều hành của máy khách (macOS, Windows, Android, iOS) và đưa nút tải bản phù hợp, các nền tảng khác liệt kê bên dưới. Tải về không cần được duyệt. Nếu máy chủ không có bản cài nào thì khung này ẩn đi.

Máy chủLuôn cóBản cài thêm lấy từ

Thư mục được đọc lại mỗi lần có người truy cập nên thêm file không cần bật lại máy chủ. Bản của chính app được ưu tiên hơn file trong thư mục cho cùng nền tảng.

Bảo mật

Dữ liệu đi bằng HTTP thường trong mạng cục bộ, không mã hoá. Chỉ máy bạn đã duyệt mới gửi được, mỗi máy có khoá phiên ngẫu nhiên riêng gắn với IP của nó. Hãy tắt máy chủ khi không dùng. Trên Windows, cho phép FileDrop trên Private networks khi tường lửa hỏi.

iOS (đang lên kế hoạch)

Bản iPhone sẽ hoạt động thế nào khi ra mắt.

  • Gửi được bất cứ lúc nào từ bảng Chia sẻ, qua Share Extension. Giữ bảng chia sẻ mở cho tới khi gửi xong.
  • Nhận chỉ khi app FileDrop đang mở. iOS tạm dừng app chạy nền, nên iPhone biến khỏi danh sách của máy khác khoảng 30 giây sau khi bạn thoát app.
  • Để không cần quyền multicast đặc biệt của Apple, iPhone tìm máy bằng cách gửi gói hỏi unicast tới từng địa chỉ trong mạng Wi-Fi thay cho broadcast. Giao thức giữ nguyên.

Thư viện lõi và kiểm thử

Build và kiểm thử riêng engine dùng chung.

cmake -S . -B build/macOS/core -DCMAKE_BUILD_TYPE=Release
cmake --build build/macOS/core -j
./build/macOS/core/shared/filedrop_tests

Bộ kiểm thử chạy 2 engine trên cùng một máy và kiểm tra: tìm thấy nhau, gửi file 3 MB cùng một thư mục lồng nhau, xử lý trùng tên, gửi từ file descriptor và chế độ tạm ẩn.

Công cụ fdcli

Một máy ảo dạng dòng lệnh, tiện đóng vai máy thứ hai trên cùng máy tính. Hãy đặt --id riêng cho nó.

# liệt kê thiết bị trong 3 giây
./build/macOS/core/shared/fdcli --id cli --name CLI list
# nhận và tự chấp nhận mọi file vào một thư mục
./build/macOS/core/shared/fdcli --id cli --name CLI --dir /tmp/in listen --yes
# gửi tới máy theo tên hoặc IP
./build/macOS/core/shared/fdcli --id cli --name CLI send "My MacBook" photo.jpg
# máy chủ nhận file qua trình duyệt, tự đồng ý mọi máy
./build/macOS/core/shared/fdcli --id cli --name CLI --dir /tmp/in web --yes --packages build/packages
Mạng cục bộ trên macOS

Công cụ chạy từ terminal có thể bị chặn truy cập mạng LAN bởi quyền Mạng cục bộ của macOS. Nếu fdcli không thấy gì, hãy cho phép app terminal trong Cài đặt hệ thống › Quyền riêng tư & Bảo mật › Mạng cục bộ.

Build cho Windows

Dùng Visual Studio trên Windows cho bản chính thức. MinGW trên Mac dùng để kiểm tra mã biên dịch được.

Cài CMake

Workload Desktop development with C++ của Visual Studio 2022 đã có sẵn CMake; dùng nó trong Developer PowerShell for VS 2022. Hoặc cài riêng:

winget install Kitware.CMake
cmake --version   # cần 3.20 trở lên

Build bằng Visual Studio 2022

Mở Developer PowerShell for VS 2022 tại thư mục gốc của repo (thư mục chứa CMakeLists.txt):

cmake -S . -B build/Windows -G "Visual Studio 17 2022" -A x64
cmake --build build/Windows --config Release

Kết quả: build\Windows\bin\Release\FileDrop.exe. Công cụ kiểm thử nằm ở build\Windows\shared\Release\. Cũng có thể mở thư mục bằng Visual Studio (File › Open › Folder) và chạy target FileDrop.exe.

Lỗi "CMakeCache.txt missing"

Bước cấu hình (cmake -S . -B …) chưa chạy xong. Chạy bước đó trước và kiểm tra nó kết thúc bằng Build files have been written to. Đừng chép thư mục build/ từ máy khác sang; hãy xoá nó rồi cấu hình lại.

Biên dịch chéo từ macOS (MinGW)

cmake -S . -B build/Windows-mingw \
  -DCMAKE_TOOLCHAIN_FILE=Windows/cmake/mingw-w64-x86_64.cmake \
  -DCMAKE_BUILD_TYPE=Release
cmake --build build/Windows-mingw

Kết quả: build/Windows-mingw/bin/FileDrop.exe, liên kết tĩnh (khoảng 16 MB), chạy trên Windows 10/11 không cần DLL kèm theo.

  2. Khai báo đường dẫn SDK trong android/local.properties: sdk.dir=/duong-dan/Android/sdk.

Giao thức

Gói điều khiển UDP dạng văn bản, sau đó một kết nối TCP cho mỗi lần truyền.

Gói UDP

Mỗi máy nghe broadcast ở cổng UDP 45454 và mở thêm một cổng điều khiển riêng, được báo trong mọi gói. Gói tin có dạng:

FILEDROP/1 ANNOUNCE
id=272a1a33cd1e48c8
ip=192.168.1.203
name=Tuyen’s MacBook Pro
os=macos
port=55754
LoạiÝ nghĩa
DISCOVERCó ai không? Gửi broadcast, kèm danh tính máy hỏi.
ANNOUNCETrả lời tên máy, IP, cổng điều khiển và hệ điều hành.
BYERời mạng (thoát app hoặc tạm ẩn).
SEND_REQUESTID yêu cầu, số file, tên file (khi 1 file), tổng dung lượng.
SEND_RESPONSEaccept=1 kèm IP, cổng TCP và mật khẩu 16 ký tự; hoặc accept=0 (kèm reason=hidden khi đang ẩn).
CANCELHủy một yêu cầu đang chờ.

Máy chủ trình duyệt (HTTP)

Trang web nằm ở shared/web/index.html và được nhúng vào thư viện lõi lúc build. Mọi request (trừ trang, /api/info và tải bản cài) đều mang khoá phiên s, phải khớp với IP đã xin kết nối.

RequestÝ nghĩa
GET /Trang web.
GET /api/infoTên máy chủ hiện trên trang, kèm apps: các bản cài có sẵn (platform, name, size).
GET /download/<platform>Tải bản cài FileDrop cho macos, windows, android… Không cần khoá phiên.
POST /api/helloBody là tên máy khách. Trả về session và client; máy chủ được hỏi có đồng ý không.
GET /api/status?known=…Long-poll (tối đa 20 giây) tới khi trạng thái khác known: pending, accepted, declined hoặc closed.
POST /api/batch?count=&total=Bắt đầu một lượt gửi (một lần thả). Kiểm tra dung lượng trống.
PUT /api/upload?b=&path=Nội dung file thô, có Content-Length. Lượt gửi hoàn tất khi đủ count file.
POST /api/batch/endMáy khách hủy lượt gửi.
POST /api/byeMáy khách ngắt kết nối.

Xử lý sự cố

Phần lớn sự cố đến từ mạng hoặc quyền truy cập.

Không thấy máy nào

  • Hai máy phải cùng mạng Wi-Fi và cùng dải mạng. Mạng khách và router bật AP / client isolation sẽ chặn các máy nói chuyện với nhau.
  • macOS: cho phép FileDrop trong Quyền riêng tư & Bảo mật › Mạng cục bộ.
  • Windows: đặt Wi-Fi là Private và cho phép FileDrop trong Windows Firewall với mạng Private.
  • Máy kia có thể đang ở chế độ tạm ẩn.
  • Bấm nút làm mới để tìm lại.

App Windows chạy nhưng không thấy gì

Tìm sau mũi tên ^ ở khay hệ thống. Nếu bản cũ vẫn đang chạy, tắt FileDrop.exe trong Task Manager trước: mỗi lúc chỉ chạy được một bản.

Truyền file bị lỗi giữa chừng

Kết nối đứng yên quá 30 giây, thường do một máy ngủ hoặc rời mạng. File nhận dở bị xoá. Hãy gửi lại.

Android không nhận file khi chạy nền

Bật Nhận file khi chạy nền và loại FileDrop khỏi chế độ tối ưu pin trong cài đặt điện thoại. Một số hãng tắt dịch vụ nền rất mạnh tay.
